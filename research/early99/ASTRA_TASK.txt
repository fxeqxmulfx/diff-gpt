Metric and fair comparison
The threshold is >=0.99 exact sequences on the complete frozen primary held-out
split, using free generation where the task requires it. The numeric vector
probes use exact generated vectors here, not their old MSE criterion. Token
accuracy, train accuracy, a partial held-out batch and teacher-forced answer
accuracy cannot substitute for the declared metric.

Epochs = actual training examples presented / fixed training-set size. With
S=ceil(N/B) updates per epoch, U completed updates expose
floor(U/S)*N + min((U mod S)*B,N) examples. This handles the short final batch and
N smaller than B. Include the zero-rate first update; exclude CUDA capture warmup.
The first-success observation and preceding observation provide the epoch bracket.
Observation cadence is fixed to min(original interval, one epoch in updates).
Do not compare the finer new stopping resolution to historical reference epochs
as though that were a model improvement.

The 60/300-second thresholds freeze membership; they are not new run timeouts.
Keep the recorded update budgets. A run that misses its budget is censored,
never a zero-epoch success or a discarded row. Record every seed, misses and
execution errors. A later drop does not undo the user's first-crossing success.
Compare identical cadence, data, batch order, dtype and evaluation between
baseline and candidate. Seconds include setup/scoring and remain recorded; epochs
are the primary objective. The user explicitly defers runtime optimization:
wall-clock speed does not affect candidate promotion or final selection.
Account for resumed clocks separately.
