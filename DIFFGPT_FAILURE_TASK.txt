Task: explain and fix the current main's DiffGPT Fibonacci learning failure
Recorded: 2026-11-10
Status: open; this task records follow-up work, not completed diagnosis.

Objective
Determine why the selected complex main misses a learning target that the
older real transformer reaches. Establish the cause with controlled native
experiments, then validate a correction without losing existing main passes.

Established evidence
The additional DiffGPT study ran 36 cells: 3 encoders (MASH, LGT, MASH-half),
1 or 2 features, seeds 11/17/23, and 1D or axial 2D positions. Every cell
completed 5000 updates without reaching 90% decoded whole-row accuracy.
Passing implementation/provenance audits did not make these learning passes.
The selected main's 75 short and 30 long passes belong to a different suite.

The older architecture and its historical recipe passed a fresh Rust/Kernite
recheck on one-feature MASH-half Fibonacci mod97. Data, split, encoded examples,
decoder bases and all sampled training IDs match the corresponding failed
native DiffGPT cells by SHA256. Final checkpoints replay metrics exactly.

All three older runs ended with 100% training accuracy. First90 is observed
every 50 updates; it is not a sustained-accuracy claim. These three passes
cover one-feature MASH-half, not the other encoder/two-feature cells.

Passing older baseline
- D128/H1/L1/V512; 262016 independent real parameters; SwiGLU hidden341.
- Unrestricted real projections, real centered XSA, standard 1D RoPE,
  attention scale 1/sqrt(128), residual gain 1, tied embedding/readout.
- Parameter-free Peri, embedding, final and per-head Q/K RMS normalization.
- ScheduleFreeAdamW: LR 0.03, betas (0.9,0.98), weight decay 1,
  epsilon 1e-8, warmup 10 updates, no clipping or cosine schedule.
- Train with query weights y; evaluate/save average weights x; preserve
  optimizer z, v, mode and counters for continuation.
- Fixed FP32 GPU arithmetic. Output projection initialization uses
  0.02/sqrt(2L), as in the historical baseline.

Failing current baseline
- Same task geometry D128/H1/L1/V512, complex FFN hidden342; complex-linear
  projections, plain complex product, ordinary causal value aggregation,
  squared-imaginary score, four-stream phase-mHC and learned LeRoPE.
- SSMax score ln(N)/d * (Re(Z) + beta*Im(Z)^2/d), with Z=sum(conj(q)*k).
- Residual branch scale 1/sqrt(2L) after output RMS normalization.
- AdamW/WSD: peak LR 0.001, betas (0.9,0.95), weight decay 0.1,
  epsilon 1e-8, independent-coordinate clip 1, 2% warmup and final 20%
  cosine decay to 1e-8. Frequencies have separate clip 1 and weight decay 0.
- FP16 forward affine operands, TF32 backward affine operands; FP32
  accumulation, remaining model math, master weights and moments.

What is known about why
The cause is not established. The evidence establishes a finite-budget
learning/generalization regression, not an inability to represent the rule.
Architecture, optimizer, schedule, initialization, independent parameter count
and arithmetic precision changed together. A 30x difference in peak learning
rate is a useful diagnostic lead, not proof that learning rate caused failure.
Both positional arms fail, so axial 2D alone cannot explain the regression.
Matching data/sampler hashes and the older passes establish that this dataset
is solvable; they do not prove every current-model implementation is correct.

Investigation
1. Inspect and replay the existing checkpoints/histories first. Verify the
   data, sampler, normalization, loss mask, argmax decoding and rounding
   identities. Compare training and held-out loss, token accuracy and decoded
   accuracy at the original 50-update cadence. Separate failure to fit training
   data from failure to generalize. Report clipping frequency, update sizes,
   score/phase/frequency evolution and any nonfinite values where available;
   obtain additional instrumentation only in explicitly registered fresh runs.

2. Cross the two complete training recipes on the two frozen architectures:
     old architecture + old recipe: existing passing baseline;
     old architecture + current recipe: new diagnostic;
     current 1D architecture + old recipe: new diagnostic;
     current 1D architecture + current recipe: existing failing baseline.
   Run the two missing combinations on seeds 11/17/23. Preserve the exact
   archived initial weights and example order within each architecture when
   changing recipes. Do not claim equivalent initialization across different
   parameterizations. For current-model frequencies retain weight decay 0;
   otherwise apply the chosen recipe's optimizer, schedule and clipping to
   all independent coordinates. Record that frequency-group adaptation.
   Validate ScheduleFree updates and x/y evaluation modes for the complex
   parameter layout against an independent Rust reference before training.
   These crosses test recipe bundles, not an isolated optimizer or LR effect.

3. Use the cross results to register focused follow-ups. If the recipe bundle
   changes the outcome, separate optimizer/averaging, LR, clipping, weight
   decay, betas and schedule with one-factor matched controls. Test fixed FP32
   affine arithmetic separately from the current mixed-precision policy,
   keeping the architecture, initial state, samples and recipe fixed.
   If an architecture gap remains, isolate attention score/temperature and
   XSA versus ordinary aggregation, SwiGLU versus complex product,
   unrestricted real versus complex-linear projections, residual routing/
   scaling, and standard versus learned rotary frequencies. Record parameter
   counts and initialization changes; use capacity-matched controls where
   possible. A recovery implicates the changed factor under the tested
   conditions; report interactions and do not assert a unique cause without
   evidence. Do not select configurations by repeatedly tuning held-out cells.

4. Confirm a proposed correction on all three one-feature MASH-half seeds,
   then evaluate all original 36 DiffGPT cells and the fixed 105-cell main
   regression suite before proposing promotion. Report every cell, regression,
   budget miss and execution error. Apply the existing main epoch/coverage
   promotion rule separately; a new-task recovery cannot erase a lost pass.
   Keep the production DiffGPT 2D positional policy and checkpoint metadata;
   historical 1D controls remain isolated research experiments.

Fixed protocol and deliverables
Use Rust and Kernite-generated PTX only; never execute Python. Keep the
original cycle-disjoint splits, encoders, domains, V512, B512, seeds, 5000
updates and 50-update observations. No extra budget or silent retries.
Preserve primary whole-row decoded accuracy, exact token accuracy as secondary,
and original-window versus forecast-reanchored decoding as separate metrics.
Validate changed kernels, adjoints, optimizer updates, checkpoint continuation
and CUDA memory/synchronization behavior before scientific comparisons.
Freeze source/binary/PTX/data/sampler identities and preregister fresh arms.
Reuse completed controls when provenance matches; preserve earlier failures.
Buffer histories; save initialization, first90, final/explicit stop and periodic
checkpoints no more frequently than every 500 epochs. Run GPU studies serially
and respect existing work. Commit authored task/source/protocol files only;
regenerable results/checkpoints stay out of commits, with the repository's
explicit exception for PTX and Kernite outputs.

Deliver a per-seed comparison, a causal explanation limited to tested evidence,
and either a validated correction or a precise account of unresolved causes.
Do not describe CPU tests, sanitizer passes or the older 105-cell suite as
successful learning on the failing additional DiffGPT tasks.
